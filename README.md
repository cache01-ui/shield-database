# S.H.I.E.L.D. — база даних оперативника

Навчальний вебзастосунок (лабораторні роботи № 1–5 з дисципліни «Web-дизайн і Web-програмування»):
клієнтська частина на HTML/CSS/JavaScript, сервер на Node.js + Express, база даних SQLite та REST API.

## Можливості

- портал, термінал авторизації з клієнтською перевіркою форми;
- каталоги досьє, матриці загроз, інцидентів і артефактів, профілі записів;
- **польові рапорти** — повний CRUD (створення, перегляд, редагування, видалення) через REST API;
- пошук і фільтрація на сервері, адаптивна верстка, доступність (ARIA, клавіатура).

## Технології

| Частина | Технології |
|---|---|
| Клієнт | HTML5, CSS3 (Flexbox, Grid), JavaScript (Fetch API, async/await) |
| Сервер | Node.js ≥ 22.13, Express 5, Helmet, express-rate-limit, compression |
| База даних | SQLite (вбудований модуль `node:sqlite`) |
| Тести | `node:test` |
| Розгортання | Render (`render.yaml`) |

## Запуск локально

```bash
npm install
npm start
```

Відкрийте http://localhost:3000. Під час першого запуску створюється файл `data/shield.db`
і наповнюється початковими даними з `server/data/*.json`.

Налаштування — у змінних середовища (див. `.env.example`; скопіюйте його в `.env`).

```bash
npm test      # автоматичні тести REST API
npm run dev   # запуск із перезапуском після змін коду
```

Для входу в термінал підходить будь-який ідентифікатор формату `ПРЕФІКС-ПРІЗВИЩЕ`
(напр. `LVL7-COULSON`) і ключ від 8 символів із літерами та цифрами (напр. `shield2026`).

## Структура

```
public/            клієнтська частина (HTML, CSS, JS, зображення)
server/
  index.js         точка входу
  app.js           Express: безпека, статика, обробка помилок
  routes.js        маршрути REST API
  validation.js    серверна перевірка даних
  db.js            схема та наповнення бази SQLite
  data/*.json      початкові дані
test/              тести API
docs/AI_LOG.md     журнал взаємодії з ШІ
render.yaml        конфігурація розгортання
```

## REST API

| Метод | Маршрут | Опис |
|---|---|---|
| GET | `/api/health` | стан сервера, кількість записів |
| GET | `/api/dossiers`, `/api/dossiers/:id` | досьє оперативників |
| GET | `/api/threats?q=`, `/api/threats/:id` | матриця загроз, пошук |
| GET | `/api/incidents?status=&sort=`, `/api/incidents/:id` | журнал інцидентів |
| GET | `/api/reports?q=&status=&priority=` | список рапортів |
| GET | `/api/reports/:id` | один рапорт |
| POST | `/api/reports` | створити рапорт → `201` |
| PUT | `/api/reports/:id` | оновити рапорт → `200` |
| DELETE | `/api/reports/:id` | видалити рапорт → `204` |

Помилки повертаються у форматі `{ "error": "...", "fields": { "поле": "повідомлення" } }`
зі статусами `400`, `404`, `413`, `429`, `500`.

## Розгортання на Render

1. Завантажте репозиторій на GitHub.
2. На https://render.com → **New → Blueprint** → оберіть репозиторій; Render прочитає `render.yaml`.
3. Після збирання застосунок буде доступний за адресою `https://shield-database-XXXX.onrender.com`.

> На безкоштовному тарифі файлова система тимчасова: після перезапуску база відновлюється
> з початкових даних, а створені рапорти зникають. Для постійного зберігання потрібен
> платний диск Render або зовнішня СУБД (PostgreSQL).
